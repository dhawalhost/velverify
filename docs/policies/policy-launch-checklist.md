# Policy Launch Checklist

Use this before publishing policies at `wardseal.com` or in the console.

## 1) Legal and ownership

- [ ] Assign legal owner for policy text
- [ ] Assign engineering owner for implementation claims
- [ ] Assign security owner for controls and incident commitments
- [ ] External counsel review completed
- [ ] Version and effective date approved

## 2) Required placeholders filled

- [x] `Wardseal`
- [x] `15 March 2026`
- [x] `privacy@wardseal.com`
- [x] `dpa@wardseal.com`
- [x] `security@wardseal.com`
- [x] `https://help.wardseal.com`
- [x] `Region-specific (India / EU-EEA / US)`
- [x] `Region-specific (India / EU-EEA / US)`

## 3) Privacy and compliance scope

- [ ] Confirm controller/processor posture for each use case
- [ ] Confirm lawful bases (GDPR/UK GDPR where applicable)
- [ ] Confirm CCPA/CPRA role and disclosure language (if applicable)
- [ ] Confirm children/minors language
- [ ] Confirm transfer mechanism language (SCCs or equivalent)

## 4) Technical truth check

- [ ] Retention periods match production configuration
- [ ] Cookie categories match actual behavior
- [ ] Incident notification window is operationally feasible
- [ ] Security controls listed are currently implemented
- [ ] Subprocessor list is current and complete

## 5) Contractual readiness

- [ ] DPA template approved
- [ ] SLA terms match support/ops capability
- [ ] Acceptable use policy mapped to enforcement actions
- [ ] ToS limitation of liability reviewed for target markets

## 6) Operational readiness

- [ ] DSAR workflow tested end-to-end
- [ ] Deletion workflow tested (including backups policy language)
- [ ] Breach escalation runbook linked and validated
- [ ] Public security reporting channel monitored

## 7) Publication

- [ ] Policies published at stable URLs
- [ ] Footer links added in landing and console apps
- [ ] API docs/reference include compliance and policy links
- [ ] Customer notification process for policy updates defined
